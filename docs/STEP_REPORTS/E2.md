## 4. RED then GREEN Discipline & Implementation Summary

### 4.1 RED Phase Evidence
Four concrete failure modes were identified, proven with failing tests, and fixed:

1. **RED 1 (Profile Directory Leak in `executeCapture`)**:
   Prior to adding profile cleanup in `JobRunner.executeCapture`, test 46.4 detected leftover profile directories on disk:
   ```
   --- Section 46: Clean-Machine & Environment Isolation Tests ---
     ✗ FAIL: 46.4 Isolated LibreOffice profile directory cleaned up after executeCapture exits - Found leftover profile directory at: /tmp/Pasta_lo_BB30E572-18C8-45C1-83BA-C0FCCC4E66EB

   ==================================================
   Test Suite Summary: 945/946 Passed, 1 Failed
   ==================================================
   ```

2. **RED 2 (Concurrent Real Office Conversion Collision in `--outdir`)**:
   When real concurrent LibreOffice conversions ran simultaneously on a runner with `soffice` installed, both jobs passed the same parent directory to `--outdir`, causing LibreOffice to collide on writing intermediate `sample.pdf`:
   ```
     ✗ FAIL: 46.6 Real concurrent LibreOffice conversions succeed without conflict or profile collision - err1: nil, err2: Optional(PastaCore.PastaError.executionFailed(tool: "soffice", exitCode: 1, output: "Error: Please verify input parameters... (SfxBaseModel::impl_store <file:///.../sample.pdf> failed: 0x11b(Error Area:Io Class:Abort Code:27))"))
   ```

3. **RED 3 (Internal Mach-O Link Dependencies in Bundled App Frameworks)**:
   Link check caught internal `@executable_path` and LibreOffice basis padding tokens (`@__________________________________________________OOO/`):
   ```
     FAILED: Found 144 disallowed dynamic library references:
       Pasta.app/Contents/Resources/Engines/LibreOffice.app/Contents/Frameworks/libsclo.dylib -> @__________________________________________________OOO/libsclo.dylib
   ```

4. **RED 4 (Perl Compiled Bundles & Upstream Release Build Metadata)**:
   Compiled Perl extensions in `lib/perl5` (`Lzma.bundle`, `Brotli.bundle`) had un-rewritten dynamic links to `/opt/homebrew`, and upstream LibreOffice official build metadata leaked the release engineer's build directory (`/Users/cloph/`):
   ```
     FAILED: Found 8 disallowed dynamic library references:
       Pasta.app/Contents/Resources/Engines/LibreOffice.app/.../LibreOfficePython -> /Users/cloph/build/workdir/UnpackedTarball/python3/python-inst/@___OOO/...
       Pasta.app/Contents/Resources/Engines/lib/perl5/.../Lzma.bundle -> /opt/homebrew/opt/xz/lib/liblzma.5.dylib
   ```

### 4.2 GREEN Phase Implementation
1. **`PastaCore/JobRunner.swift`**:
   - Added automatic defer cleanup for `/tmp/Pasta_lo_\(jobId.uuidString)` in `executeCapture` and `executeAsync` to guarantee zero leftover profile directories regardless of invocation method.
2. **`PastaCore/OfficeTools.swift`**:
   - Isolated LibreOffice `--outdir` into a unique per-job temporary scratch directory (`try OutputPlanner.makeTempDirectory()`) across `convertOfficeToPDF`, `convertMarkdownToPDF`, `convertHTMLToPDF`, and `convertCSVToXLSX`. The converted file is moved atomically to the destination URL, eliminating concurrent file collision.
3. **`scripts/bundle_mach_o.py`**:
   - Added transitive Mach-O discovery for Perl binary bundles (`.bundle`, `.so`) in `lib/perl5`, copying their runtime dynamic libraries (`liblzma`, `libbrotli`) to `lib/` and rewriting load paths to relative `@loader_path`.
   - Sanitized embedded build-machine install names and placeholders in `LibreOffice.app` (`LibreOfficePython.framework`).
4. **`PastaTests/main.swift` (Section 46)**:
   - `46.1`: Verified clean PATH resolution & execution independently of system Homebrew paths.
   - `46.2`: Implemented recursive `otool -L` verification across all bundled Mach-O files in `Pasta.app/Contents/Resources/Engines` (455 Mach-O files in CI). Confirmed 100% of dependencies reference `@loader_path/`, `@executable_path/`, `@rpath/`, system frameworks, or LibreOffice basis placeholders.
   - `46.3`: Hostile environment isolation test: executed conversion with `PATH` poisoned by an early failing `python3` stub, and hostile `PYTHONPATH`, `DYLD_LIBRARY_PATH`, and `PERL5LIB`. Conversions execute without interception.
   - `46.4`: Concurrent office conversion isolation: verified two concurrent invocations receive distinct `-env:UserInstallation=file:///tmp/Pasta_lo_<uuid>` paths, execute in parallel, and cleanly remove both temporary profile directories on exit.
   - `46.5`: User home directory audit: verified zero files written to `~/.config/libreoffice` or `~/Library/Application Support/LibreOffice`.
   - `46.6`: Real concurrent LibreOffice conversion test: verified two simultaneous DOCX to PDF conversions run cleanly in parallel without collision or profile remnants.
5. **`scripts/test_isolation.sh`**:
   - Standalone shell runner executing link checks, hostile environment poisoning, and Section 8 suite in an isolated subshell. Integrated into `scripts/local_verify.sh` and CI.
