## 1. Scope & Plan Requirements

Following `docs/PHASE_P_PRODUCT_PLAN.md` (Step E7):
1. **Trigger & Permission States**:
   - `WheelTriggerState`: `.enabled` vs `.paused` (saved to `PreferencesManager.shared.wheelEnabled`).
   - `AccessibilityState`: `.missing`, `.granted`, `.revoked` (computed via `AccessibilityPermissionProvider` and `hasEverGrantedAccessibility` preference history).
   - `LaunchAtLoginState`: `.enabled` vs `.disabled` (controlled via `LaunchAtLoginProvider` using `SMAppService` on macOS 13+).
   - `EffectiveTriggerStatus`: `.active`, `.pausedByUser`, `.waitingForAccessibility`, `.accessibilityRevoked`.
2. **Transition Rules & Automatic Lifecycle Control**:
   - **Cold launch without prior grant and untrusted**: `accessibilityState = .missing`, `effectiveStatus = .waitingForAccessibility`, monitoring remains stopped.
   - **Cold launch with prior grant (`hasEverGrantedAccessibility == true`) and untrusted**: `accessibilityState = .revoked`, `effectiveStatus = .accessibilityRevoked`, monitoring remains stopped.
   - **Cold launch when trusted**: `accessibilityState = .granted`, `hasEverGrantedAccessibility = true`. If `wheelState == .enabled`, `effectiveStatus = .active` and `monitorController.startMonitoring()` is called immediately.
   - **Auto-Start Without Restart**: When permission is granted while running (detected via polling or event), state transitions from `.missing` or `.revoked` to `.granted`, `effectiveStatus` becomes `.active`, and `monitorController.startMonitoring()` is invoked immediately without application restart.
   - **Immediate Revocation Handling**: When permission is revoked in System Settings, state transitions to `.revoked`, `effectiveStatus` becomes `.accessibilityRevoked`, and `monitorController.stopMonitoring()` is invoked immediately.
   - **User Pause/Unpause**: User setting `wheelState = .paused` immediately halts monitoring (`monitorController.stopMonitoring()`) and reports `.pausedByUser`. Unpausing transitions back to `.active` and starts monitoring if permission is granted; if permission is missing or revoked, it reports `.waitingForAccessibility` or `.accessibilityRevoked` without starting monitoring.
   - **Launch-At-Login**: Managed via `LaunchAtLoginProvider` protocol. Provider errors are cleanly caught and propagated while preserving previous state.
   - **Auto-Polling**: Timer-based polling mechanism (`startAutoPolling`, `stopAutoPolling`, `pollTick`) continuously monitors permission transitions.
3. **Purity & Safety**:
   - Zero network APIs or tracking.
   - Abstracted protocols (`AccessibilityPermissionProvider`, `LaunchAtLoginProvider`, `DragMonitorLifecycleController`) ensure tests run headlessly in clean sandboxes without touching global OS events.
