# Step Report: F2 — Remove the Invented Budget (Size is Report-Only)

**Date:** 2026-11-07  
**Branch:** `fix/step-f2-remove-size-budget`  
**Status:** Completed & Verified  

---

## 1. Executive Summary

An external audit of Stage 1 identified that a 500 MB hard budget limit was invented (`scripts/measure_bundle_size.sh` hardcoded `BUDGET_MB=500.0`, failing or gatekeeping builds). The project owner's explicit decision was: **NO size limit for the first build; size is strictly report-only.**

Step F2 aligns the build tooling, CI workflows, and test assertions with the owner's decision:
1. `scripts/measure_bundle_size.sh` was rewritten: removed `BUDGET_MB`, `BUDGET_BYTES`, `within_budget`, and PASS/FAIL against budget.
2. Structured breakdown table was implemented: each individual engine binary/bundle, relocatable bundled engines total, app executable binary, licenses directory, core framework build, and release archive (zip/dmg).
3. The build script never fails for size.
4. A safety warning guard was implemented: if the release archive or app bundle exceeds 1.8 GiB, CI and local runs print a clear warning (`WARNING: Release archive ... exceeds 1.8 GiB threshold!`), keeping the asset within GitHub Release limits (~2 GiB per file).
5. All assertions enforcing the 500 MB budget were removed and updated to report-only validation.
