## 1. Scope & Plan Requirements

Following `docs/PHASE_P_PRODUCT_PLAN.md` (Step E5):
1. **Config File**: One centralized config file (`PastaCore/Resources/heavy_job_limits.json`) defining per-category limits and cost estimates:
   - Video: `duration * pixels * codec_factor` via media probe
   - Audio: `duration`
   - Image: `megapixels` (`(width * height) / 1,000,000`)
   - PDF: `pages`
   - Archives: `declared_uncompressed_bytes`
   - OCR: `pages`
2. **Needs Confirmation Result**: Exceeding a limit returns `needsConfirmation = true` with warning metadata and zero precise time promises.
3. **Engine QoS**: All child engine processes are launched with `Process.qualityOfService = .utility`.
4. **Pause and Resume**: Running jobs support pausing via `kill(pid, SIGSTOP)` and resuming via `kill(pid, SIGCONT)`, tracked via `JobRunner.isJobPaused`.
5. **Disk Space Safety Check**: Validates free space on destination volume against estimated output size (`estimatedBytes * safetyBufferMultiplier + minimumHeadroomBytes`); fails gracefully with `PastaError.insufficientDiskSpace(availableBytes:requiredBytes:)`.
6. **Concurrency Guard**: Strictly enforces at most one heavy job active at a time across the application (`guard.tryAcquireHeavyJobSlot` / `guard.releaseHeavyJobSlot`).
7. **Thermal Protection & Battery Flagging**: Monitors `ProcessInfo.thermalState` via protocol-injected `ThermalStateProvider`. At `.serious` or `.critical`, automatically pauses active heavy jobs; automatically resumes upon cooldown to `.nominal` or `.fair`; supports explicit user resume override; flags jobs running on battery power.
8. **Test-Driven Discipline**: Executed with strict RED then GREEN verification (stubbed initial failures, then passing implementations).
