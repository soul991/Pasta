## 1. Scope & Plan Requirements

Following `docs/PHASE_P_PRODUCT_PLAN.md` (Step E6):
1. **Trash Destination Only**: Original files are moved to the system **Trash**, never permanently deleted (`FileManager.default.trashItem(at:resultingItemURL:)` abstracted through `TrashProvider`). Permanent deletion (`removeItem(at:)` or `unlink`) is never used on source files.
2. **Verification Gate Before Trashing**: Trashing occurs only after the output file has been verified:
   - Output exists on disk.
   - Output file size is > 0 bytes (non-empty).
   - Output file extension/type matches the declared action expectation.
   - Job reported success (`JobExecutionStatus.success`).
   - Original is **never** trashed on failure, cancellation, or partial output.
3. **Skip & Report Reasons**: Aborts trashing and records a structured skip reason for:
   - Read-only volumes or unwritable parent directories (`.readOnlyVolume`, `.cannotTrash`).
   - Source canonical path equals output canonical path (`.sourceEqualsOutput`).
   - Source modified during conversion (`.sourceModifiedDuringConversion`): validated via pre-conversion `SourceSnapshot` checking mtime, file size, and SHA-256 hash.
   - Preference disabled or unconfirmed (`.preferenceDisabledOrUnconfirmed`).
4. **Stored Double-Confirmation Guard**: The delete-original setting can only be enabled through a stored cryptographic confirmation record (`PreferencesManager.shared.enableDeleteOriginal(confirmationPhrase:)`). Setting `defaults write` or flipping the boolean flag directly without a valid cryptographic token evaluates to `deleteOriginalEnabled == false`.
5. **JobRunner Integration**: Automatically takes a pre-conversion snapshot in `JobRunner.run` and `JobRunner.runBatch`, executing `DeleteOriginalGuard.execute` after atomic publication of verified output.
6. **Test-Driven Discipline**: Verified with strict RED then GREEN testing across all rules (missing output, zero-byte output, cancelled job, read-only source, collision, modified source, and confirmation token validation).

## 5. Implementation Files

1. **`PastaCore/DeleteOriginalGuard.swift`**:
   - `TrashProvider` protocol & `SystemTrashProvider` (using `FileManager.default.trashItem`) & `MockTrashProvider` for deterministic testing.
   - `SourceSnapshot`: Captures file size, mtime, and SHA-256 hash before conversion; verifies whether source was mutated during conversion.
   - `DeleteOriginalDecision`: Pure domain decision (`approved` or `rejected(reason)`).
   - `DeleteOriginalSkipReason`: Structured reasons for skipping deletion (missing output, zero-byte output, type mismatch, failed job, cancelled job, collision, read-only volume, untrashable, modified source, disabled preference).
   - `DeleteOriginalGuard.generateConfirmationRecord` & `validateConfirmationRecord`: Cryptographic signature binding timestamp and required phrase (`"I understand deleted files are moved to the Trash"`).
   - `DeleteOriginalGuard.assess` & `execute`: Pure logic verification and trashing.
2. **`PastaCore/PreferencesManager.swift`**:
   - `deleteOriginalEnabled`: Getter validates both the user default boolean and the cryptographic confirmation record. Setter refuses enablement unless backed by a valid stored confirmation.
   - `enableDeleteOriginal(confirmationPhrase:)`: Validates phrase and stores cryptographic confirmation token.
   - `disableDeleteOriginal()`: Clears preference and stored confirmation record.
3. **`PastaCore/JobRunner.swift`**:
   - Integrated pre-conversion snapshot capture in `run` and `runBatch`.
   - Post-publication execution of `DeleteOriginalGuard.execute` when enabled.
4. **`PastaTests/main.swift` (Section 50)**:
   - Added 30 assertions comprehensively testing all rules and safety gates.
