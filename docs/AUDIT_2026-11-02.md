8. `37.2 VisionOCRTools recognizes known text from generated image fixture`
   (Vision returned `PASTA OCR ACCURATE TEST 20`).
9. `37.3 Watermark text 'PASTA_SECRET_STAMP' present in output via pdftotext`.

Seven of these nine failures are assertions that `soffice` is absent: failures
1–7. They fail in CI because the WIP workflow installs LibreOffice, not because
those Office conversions have been proven broken. The rewrite must use
`ToolLocator` overrides for hermetic missing-tool and present-tool unit cases,
and have exactly one real LibreOffice integration test guarded by actual
`soffice` availability.

The OCR fixture is objectively too narrow: it draws 32-point
`PASTA OCR ACCURATE TEST 2026` into a 500×120 canvas beginning at x=20. Vision
recognizes the visible prefix (`...TEST 20`); enlarge the canvas before treating
recognition of `2026` as a product failure.

The watermark exists but the assertion is wrong for a diagonal stamp. I
reproduced the WIP CoreText stamp at its exact 45° transform. `pdftotext`
extracts the glyphs in rotated geometric order with intervening newlines
(`PA`, `ST`, `A`, ...), not as the contiguous string
`PASTA_SECRET_STAMP`; the same happens after `qpdf --overlay`. The horizontal
page-number test passes because it is not rotated. Verify diagonal watermark
visibility by rendering/image comparison and test its text content with a
rotation-aware extraction or a non-diagonal test stamp.
